The Hedra MCP server is `https://mcp.hedra.com`. Add that URL to an MCP client
and sign in with your Hedra account. Your client can use the tools exposed by the
server to discover models, inspect their inputs, estimate supported jobs, run
media workloads, and retrieve results from your Hedra library.

## Choose how to connect

| Integration | Use it for | Authentication and billing |
| --- | --- | --- |
| MCP server | Let an assistant call Hedra's available tools | Hedra sign-in; selected workspace and billing mode in [MCP settings](https://www.hedra.com/develop/mcp) |
| CLI | Inspect model contracts, submit jobs, and manage API operations from a terminal | `hedra-cli auth login` or an API key; v3 API wallet |
| REST API / compatible SDK | Call image-understanding and reasoning models or integrate asynchronous model jobs into your application | API key and prepaid v3 API wallet |

MCP does not require you to paste an API key into the assistant. Use your Hedra
subscription or pay as you go according to the selected MCP billing mode.
The CLI and REST API use the API wallet; Studio subscription credits are separate.

For image understanding and reasoning through the API, use the
[chat completions guide](/pages/developer/v3/chat-completions). Models in the API
catalog and tools exposed by an MCP connection are different inventories: check
your client's tool list before requesting a capability. To use Hedra as the
language-model provider for a coding assistant, see
[Coding agents](/pages/developer/v3/coding-agents).

## Add the server

<Tab title="Claude">

<Steps>

[Add to Claude](https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=Hedra&connectorUrl=https%3A%2F%2Fmcp.hedra.com)
opens claude.ai's **Add custom connector** dialog with the name `Hedra` and the

<Step title="Connect and sign in">

Click **Add**, then **Connect**, and finish the Hedra sign-in.

</Step>
</Steps>

</Tab>

```bash
claude mcp add --transport http hedra https://mcp.hedra.com
```

Run `/mcp` and complete the Hedra sign-in in the browser window it opens.

</Tab>
<Tab title="Codex">

```bash
codex mcp add hedra --url https://mcp.hedra.com
```

Start Codex and approve the Hedra sign-in when it prompts you.

</Tab>
<Tab title="Cursor">

[Add to Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=hedra&config=eyJ1cmwiOiJodHRwczovL21jcC5oZWRyYS5jb20ifQ%3D%3D)

```json
{
  "mcpServers": {
    "hedra": { "url": "https://mcp.hedra.com" }
  }
}
```

Reload Cursor, then sign in to Hedra from the MCP panel.

</Tab>
<Tab title="ChatGPT">

Open **Settings → Apps**, add a custom app, and paste `https://mcp.hedra.com`.
Some plans need developer mode on first. Then authorize Hedra.

</Tab>
<Tab title="Hermes">

Add this to `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  hedra:
    url: "https://mcp.hedra.com"
    auth: oauth
```

Hermes opens the Hedra sign-in and keeps the token after the OAuth callback.

## Inspect a model before running it

Start with a read-only discovery task:

```text
Use Hedra to list the models available through this connection. Inspect the input requirements of one model suitable for my task. Do not submit a job yet.
```

The server exposes `list_models` and `get_model` for model discovery. For a
supported media job, use `estimate` with the intended inputs before asking the
client to run it. Confirm the selected workspace and billing mode in
[MCP settings](https://www.hedra.com/develop/mcp).

When you run a job, name the model, provide its required inputs, and retrieve the
result through the tools available in your client. Image, video, speech, music,
and sound-effect tools remain available for those workloads; they do not imply
that every model or REST endpoint has a corresponding MCP tool.

## Generate a synthetic research image

After checking your workspace and billing mode, try this generation task:

```text
Use Hedra to generate one synthetic image for a scene-understanding experiment: a workbench with three distinct tools, a partially obscured box, and an empty shelf. Choose a suitable image model, check its inputs and estimated cost, then generate the image. Return the result with the model and parameters so I can reproduce the setup.
```

This submits a billable generation job. Save the returned model, parameters, and
image for your experiment; the example does not run a perception evaluation or
train a model. For work with Hedra researchers, see
[Custom models and serving](/pages/developer/v3/custom-models).

## Inspect the same catalog from the CLI

```bash
npm install --global @hedra/cli
hedra-cli models list
hedra-cli models get --model glm-5.3
```

Model discovery is available without credentials. For authenticated operations,
run `hedra-cli auth login`, complete the browser sign-in, and check the workspace
with `hedra-cli auth status`. Use `hedra-cli <resource> --help` to see the commands
in your installed version. See the [CLI command reference](https://github.com/hedra-labs/hedra-cli#commands).

## If the client reports 404

The server URL is `https://mcp.hedra.com` on its own. A connector saved with a
curl command, or with an `api.hedra.com` URL, gets 404 from every chat that uses
it. Remove that connector and add the URL above. The REST API at
`api.hedra.com` is for code you write, with an API key; the
[quickstart](/pages/developer/v3/quickstart) covers it.
