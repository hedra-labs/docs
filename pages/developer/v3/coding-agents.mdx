Codex CLI, OpenCode and Pi can run on the open-weight LLMs that `POST /v3/chat/completions` serves, and Hedra charges each request they send to your API wallet. OpenCode and Pi send Chat Completions requests, so they call Hedra directly. Codex sends requests only in the format of OpenAI's Responses API, which Hedra does not serve, so it calls Hedra through LiteLLM: an open-source proxy that runs on your machine and converts each Responses request into a Chat Completions request.

## Before you start

- **A key with the `chat:write` scope and a funded API wallet.** See [Before you start](/pages/developer/v3/chat-completions#before-you-start) in the chat completions guide.
- **The key in the `HEDRA_KEY` environment variable** of the terminal that starts the agent or LiteLLM:

```bash
export HEDRA_KEY="<key_id>:<secret>"
```

## Choose a model

| Model | Input, per 1M tokens | Output, per 1M tokens | Price and time of one OpenCode run |
| --- | --- | --- | --- |
| `zai-org/glm-5.3` | \$1.40 | \$4.40 | \$0.41, 79 s |
| `zai-org/glm-5.3-flash` | \$0.15 | \$0.50 | \$0.02, 35 s |
| `moonshotai/kimi-k3` | \$3.00 | \$15.00 | \$0.77, 83 s |
| `deepseek-ai/deepseek-v4-pro-0813` | \$1.32 | \$3.96 | \$0.36, 141 s |
| `deepseek-ai/deepseek-v4.1-flash` | \$0.30 | \$1.20 | \$0.05, 27 s |

On 2026-09-30 we had OpenCode, on each model, write unit tests for one module of a large Python repository and run them until they passed. Every model's run finished, in 8 to 14 requests with prompts of up to 25,000 tokens. Every model's context length is 1,048,576 tokens. `deepseek-ai/deepseek-v4-pro-0813` takes text only: a request to it that carries an image returns `400`.

## Connect an agent

<Tabs>
<Tab title="Codex CLI">

The steps below use Codex CLI 0.159.2 and LiteLLM 1.103.1. Codex 0.134 and later read each profile from a file of its own, `~/.codex/<name>.config.toml`, as in step 4.

<Steps>
<Step title="Install LiteLLM">

```bash
uv tool install 'litellm[proxy]'
```

</Step>
<Step title="Configure LiteLLM">

Save this as `litellm.yaml`:

```yaml
model_list:
  - model_name: "*"
    litellm_params:
      model: openai/*
      api_base: https://api.hedra.com/v3
      api_key: os.environ/HEDRA_KEY
      use_chat_completions_api: true
      max_tokens: 32768
```

</Step>
<Step title="Start LiteLLM">

```bash
litellm --config litellm.yaml --host 127.0.0.1 --port 4000
```

Leave it running while you use Codex.

</Step>
<Step title="Add a Codex profile">

Save this as `~/.codex/hedra.config.toml`:

```toml
model = "zai-org/glm-5.3"
model_provider = "hedra"
model_reasoning_effort = "high"
web_search = "disabled"

[model_providers.hedra]
name = "Hedra"
base_url = "http://127.0.0.1:4000/v1"
```

</Step>
<Step title="Start Codex">

In a second terminal:

```bash
codex --profile hedra
```

Codex prints `Model metadata for zai-org/glm-5.3 not found. Defaulting to fallback metadata; this can degrade performance and cause issues.` The session runs with the fallback metadata.

</Step>
</Steps>

| Setting | Effect |
| --- | --- |
| `model_name: "*"` with `model: openai/*` | LiteLLM forwards any model id, so `codex --profile hedra --model moonshotai/kimi-k3` switches models. |
| `use_chat_completions_api: true` | LiteLLM sends Chat Completions requests. Without it, LiteLLM forwards each Responses request to `https://api.hedra.com/v3/responses`, which returns `404`. |
| `max_tokens: 32768` | Codex sets no output limit, so without this each request gets Hedra's default of 4,096 output tokens, which a reasoning model can spend before it calls a tool. 32,768 is the largest limit every chat model accepts. |
| `model_reasoning_effort = "high"` | Codex applies each setting of `~/.codex/config.toml` that the profile does not set, and Hedra returns `400` for Codex's `minimal`, `medium` and `xhigh`. `low` and `max` also work. |
| `--host 127.0.0.1` | LiteLLM accepts connections from this machine only. By default it listens on every network interface and sends any request it receives to Hedra with your key. |
| `web_search = "disabled"` | Codex leaves out its web search tool. LiteLLM converts that tool into the `web_search_options` field, and Hedra returns `400` for that field. |

| Setting | Effect |
| --- | --- |
| `"apiKey": "$HEDRA_KEY"` | Pi reads the key from `HEDRA_KEY`. Without the `$`, Pi sends the text `HEDRA_KEY` as the key. |
| `"supportsStore": false` | Pi leaves out the `store` field, and Hedra returns `400` for that field. |

## What a session costs

An agent sends the whole conversation with every request: its instructions, its tool definitions, and every earlier message, model response and tool output. The prompt grows with each request, and Hedra charges every prompt token at the model's input price. A session's price is the sum, over its requests, of the prompt tokens times the input price and the output tokens times the output price.

On 2026-09-30, Codex answered one question about a repository in 7 requests to `zai-org/glm-5.3`, with 15 MCP servers enabled. Codex sends every tool of every enabled MCP server with every request, and each request carried about 187,000 prompt tokens. Without MCP servers, Codex's first request is about 40 KB, which is at most 40,000 tokens because every token is at least one byte.

| | Tokens | Price per 1M tokens | Price |
| --- | --- | --- | --- |
| Prompt, 7 requests | 1,306,128 | \$1.40 | \$1.83 |
| Output, 7 requests | 795 | \$4.40 | \$0.004 |

To shorten every request's prompt:

- **Turn off the MCP servers you do not need.** In Codex, add an entry to `~/.codex/hedra.config.toml` for each server in `~/.codex/config.toml`:

  ```toml
  [mcp_servers.linear]
  enabled = false
  ```

  In OpenCode, set `"mcp": { "linear": { "enabled": false } }` in `opencode.json`. With its default MCP `exposure`, `codemode`, Pi declares no MCP tools to the model.
- **Keep `AGENTS.md` short.** Codex, OpenCode and Pi add the repository's `AGENTS.md` to the instructions they send with each request of the conversation.
- **Leave Claude Code's files out of OpenCode.** OpenCode adds `~/.claude/CLAUDE.md` to its prompt when `~/.config/opencode/AGENTS.md` does not exist, and lists the name and description of each skill in `~/.claude/skills`. Set `OPENCODE_DISABLE_CLAUDE_CODE=1` to leave both out.

`GET /v3/usage` returns what the key's user spent on each model since `start`: `jobs` counts the chat requests, and `spent` is their net price. The key needs the `usage:read` scope.

```bash
curl "https://api.hedra.com/v3/usage?start=2026-09-30T21:00:00Z&group_by=model" \
  -H "Authorization: Key $HEDRA_KEY"
```

## Holds and 402s

Before each request, Hedra holds the request's largest possible price on your API wallet. It counts each byte of the prompt, tool definitions included, as one token, up to the model's context length, and prices those tokens at the input price and `max_tokens` at the output price. When the response ends, Hedra keeps the price of the tokens the model used and returns the rest ([Billing and concurrency](/pages/developer/v3/chat-completions#billing-and-concurrency)). A request to `moonshotai/kimi-k3` with a 400,000-byte prompt and `max_tokens: 32000` holds \$1.68: \$1.20 for the prompt and \$0.48 for the output. When your balance cannot cover a request's hold, the request returns `402`. Keep more in the wallet than the holds of the requests your agent runs at once.
