Hedra serves open-weight LLMs through `POST /v3/chat/completions`, which speaks the OpenAI chat-completions format. Point the stock OpenAI SDK at `https://api.hedra.com/v3`, use your Hedra API key, and every request is billed per token from the same prepaid API wallet as your media jobs.

## Before you start

- **A key with the `chat:write` scope.** Create one in the [developer console](https://www.hedra.com/develop/api-keys).
- **A funded API wallet.** An empty wallet returns `402` on every request. Add funds in the [developer console](https://www.hedra.com/develop/billing).

## Authenticate

The OpenAI SDK sends `api_key` as `Authorization: Bearer <api_key>`. Hedra reads a Bearer value with a colon as an API key, so pass your key in its `<key_id>:<secret>` form:

<CodeGroup>

```python Python
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://api.hedra.com/v3",
    api_key=os.environ["HEDRA_KEY"],  # "<key_id>:<secret>"
)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.hedra.com/v3",
  apiKey: process.env.HEDRA_KEY, // "<key_id>:<secret>"
});
```

</CodeGroup>

A legacy `sk_hedra_…` key has no colon, so Hedra rejects it as a Bearer value. Send it with the `Key` scheme instead, which replaces the header the SDK would send:

<CodeGroup>

```python Python
client = OpenAI(
    base_url="https://api.hedra.com/v3",
    api_key="unused",
    default_headers={"Authorization": f"Key {os.environ['HEDRA_LEGACY_KEY']}"},
)
```

```typescript TypeScript
const client = new OpenAI({
  baseURL: "https://api.hedra.com/v3",
  apiKey: "unused",
  defaultHeaders: { Authorization: `Key ${process.env.HEDRA_LEGACY_KEY}` },
});
```

</CodeGroup>

## Choose a model

`GET /v3/llms` lists every model in the OpenAI model-object format, with each model's context length, capabilities and price per million input and output tokens. `GET /v3/llms/{model}` returns one. Neither needs a key.

```bash
curl https://api.hedra.com/v3/llms
```

`client.models.list()` does not return these models: the SDK calls `GET /v3/models`, which lists Hedra's image, video and audio models. Call `GET /v3/llms` directly.

## Send a request

<CodeGroup>

```python Python
response = client.chat.completions.create(
    model="glm-5.3",
    messages=[{"role": "user", "content": "Write a haiku about latency."}],
)
print(response.choices[0].message.content)
```

```typescript TypeScript
const response = await client.chat.completions.create({
  model: "glm-5.3",
  messages: [{ role: "user", content: "Write a haiku about latency." }],
});
console.log(response.choices[0].message.content);
```

</CodeGroup>

### Stream the response

Pass `stream: true`. To receive token counts in the last chunk, also pass `stream_options: {"include_usage": true}`.

<CodeGroup>

```python Python
stream = client.chat.completions.create(
    model="glm-5.3",
    messages=[{"role": "user", "content": "Explain SSE in two sentences."}],
    stream=True,
    stream_options={"include_usage": True},
)
for chunk in stream:
    if chunk.choices:
        print(chunk.choices[0].delta.content or "", end="")
    if chunk.usage:
        print(f"\n{chunk.usage.prompt_tokens} in, {chunk.usage.completion_tokens} out")
```

```typescript TypeScript
const stream = await client.chat.completions.create({
  model: "glm-5.3",
  messages: [{ role: "user", content: "Explain SSE in two sentences." }],
  stream: true,
  stream_options: { include_usage: true },
});
for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
  if (chunk.usage) {
    console.log(`\n${chunk.usage.prompt_tokens} in, ${chunk.usage.completion_tokens} out`);
  }
}
```

</CodeGroup>

If the model fails after the stream has started, the stream carries one event of the form `data: {"error": {"message": ..., "type": "server_error", "code": "upstream_error"}}` and then ends. The OpenAI SDK raises it as an `APIError`. The charge covers the prompt and the tokens streamed before the failure. The same holds when your client disconnects mid-stream.

### Call tools and request JSON

Models whose `capabilities.tools` is `true` in `GET /v3/llms` accept `tools` and `tool_choice`. Models that list `json_object` in `capabilities.response_format_types` accept `response_format: {"type": "json_object"}`.

<CodeGroup>

```python Python
response = client.chat.completions.create(
    model="glm-5.3",
    messages=[{"role": "user", "content": "What's the weather in Paris?"}],
    tools=[
        {
            "type": "function",
            "function": {
                "name": "get_weather",
                "description": "Current weather for a city",
                "parameters": {
                    "type": "object",
                    "properties": {"city": {"type": "string"}},
                    "required": ["city"],
                },
            },
        }
    ],
)
call = response.choices[0].message.tool_calls[0]
print(call.function.name, call.function.arguments)

json_response = client.chat.completions.create(
    model="glm-5.3",
    messages=[{"role": "user", "content": "List three primes as {\"primes\": [...]}"}],
    response_format={"type": "json_object"},
)
```

```typescript TypeScript
const response = await client.chat.completions.create({
  model: "glm-5.3",
  messages: [{ role: "user", content: "What's the weather in Paris?" }],
  tools: [
    {
      type: "function",
      function: {
        name: "get_weather",
        description: "Current weather for a city",
        parameters: {
          type: "object",
          properties: { city: { type: "string" } },
          required: ["city"],
        },
      },
    },
  ],
});
const call = response.choices[0].message.tool_calls?.[0];

const jsonResponse = await client.chat.completions.create({
  model: "glm-5.3",
  messages: [{ role: "user", content: 'List three primes as {"primes": [...]}' }],
  response_format: { type: "json_object" },
});
```

</CodeGroup>

## Accepted request fields

`model`, `messages`, `frequency_penalty`, `logit_bias`, `logprobs`, `top_logprobs`, `max_tokens`, `max_completion_tokens`, `n` (only `1`), `presence_penalty`, `reasoning_effort`, `response_format`, `seed`, `stop`, `stream`, `stream_options`, `temperature`, `tool_choice`, `tools`, `parallel_tool_calls`, `top_p` and `user`.

Any other field returns `400` naming the field. A field the model does not support, such as `tools` on a model without tool calling, also returns `400`.

## Billing

Each request is charged the model's price per million input and output tokens, from your API wallet, when the response finishes. `GET /v3/usage/llm` lists each request with its model, token counts and charge. `GET /v3/transactions` shows chat charges summed per model per UTC day.

## Where Hedra differs from OpenAI

| Situation | OpenAI | Hedra |
| --- | --- | --- |
| Empty or underfunded wallet | `429 insufficient_quota` | `402`. Retrying does not help; add funds. |
| Listing models | `client.models.list()` | `GET /v3/llms` |
| Model at capacity, or too many requests in flight on one key | `429` | `429` with a `Retry-After` header. The SDK retries it. |
| API key in `Authorization: Bearer` | any key | `<key_id>:<secret>` keys only |
