title: "Generate a Video"
description: "Generate text-to-video and image-to-video with the Hedra API — upload keyframes, submit a request, and read per-model input constraints and defaults."
---

All examples use the base URL `https://api.hedra.com/web-app/public` and require an `X-API-Key` header.

```bash
export HEDRA_API_KEY="your_api_key"
```

## Text-to-video

Generate a video from a text prompt alone using Grok Video T2V
(`fal/grok-video-t2v`):

```bash
curl -X POST https://api.hedra.com/web-app/public/generations \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $HEDRA_API_KEY" \
  -d '{
    "type": "video",
    "model_slug": "fal/grok-video-t2v",
    "generated_video_inputs": {
      "text_prompt": "A woman walking through a busy market at golden hour",
      "aspect_ratio": "16:9",
      "resolution": "720p",
      "duration_ms": 5000
    }
  }'
```

## Image-to-video

Generate a video from a start image using Grok Video I2V
(`fal/grok-video-i2v`).

### Step 1: Upload a start image

```bash
# Create the asset record
curl -X POST https://api.hedra.com/web-app/public/assets \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $HEDRA_API_KEY" \
  -d '{
    "name": "my-image.png",
    "type": "image"
  }'

# Upload the file
curl -X POST https://api.hedra.com/web-app/public/assets/{asset_id}/upload \
  -H "X-API-Key: $HEDRA_API_KEY" \
  -F "file=@/path/to/image.png"
```

### Step 2: Generate the video

```bash
curl -X POST https://api.hedra.com/web-app/public/generations \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $HEDRA_API_KEY" \
  -d '{
    "type": "video",
    "model_slug": "fal/grok-video-i2v",
    "start_keyframe_id": "{image_asset_id}",
    "generated_video_inputs": {
      "text_prompt": "The scene comes to life with gentle movement",
      "aspect_ratio": "16:9",
      "resolution": "720p",
      "duration_ms": 5000
    }
  }'
```

## Required fields

| Field | Description |
|-------|-------------|
| `type` | Set to `"video"` |
| `generated_video_inputs.text_prompt` | Text description of the video content |

## Optional fields

| Field | Description |
|-------|-------------|
| `model_slug` | The model slug to use (see `GET /models?types=video`) |
| `start_keyframe_id` | Asset ID of the start image (required for I2V models) |
| `end_keyframe_id` | Asset ID of the end image |
| `generated_video_inputs.aspect_ratio` | e.g. `"16:9"`, `"9:16"`, `"1:1"` |
| `generated_video_inputs.resolution` | e.g. `"540p"`, `"720p"` |
| `generated_video_inputs.duration_ms` | Duration in milliseconds |
| `batch_size` | Generate 1-8 variations at once (default: 1) |

<Note>
  When `batch_size` is greater than 1, include a `generation_ids` array containing
  one client-generated UUID for each variation.
</Note>

## Discover model constraints and defaults

`GET /models?types=video` is the source of truth for what a given video model
will accept. For each input slot the response publishes:

- `max_file_size_bytes` for start frames, end frames, and source videos (up to
  the 30 MB image / 500 MiB video platform ceilings, tightened per model — for
  example, Veo 3.1 caps input frames at 20 MB).
- `min_dimension_px` and `max_dimension_px` for image frames where the model
  declares a floor or ceiling.
- `min_duration_ms` and `max_duration_ms` on source-video slots, and
  `max_total_duration_ms` across a multi-file audio-reference slot (for
  example, Seedance 2.0 accepts up to 15 seconds of reference audio in total).

The response also publishes a JSON Schema `default` for any dispatch-shaping
field the model resolves on your behalf — for example, veed-fabric-10 defaults
`resolution` to `"720p"`. Where no default is published (for example,
`duration_ms` on a model that lists more than one length), the field is
effectively required: omit it and the request will fail rather than fall back
to a chosen length.

For models that expose multiple modes behind a discriminator (for example,
Minimax Hailuo's `quality: standard` versus `quality: pro`), the schema
publishes an `anyOf` of `required` branches — one branch per mode. This lets
you tell before you submit which sizing fields your chosen mode demands: on
Minimax Hailuo, `quality: standard` requires `duration_ms` while `quality: pro`
does not.

`text_prompt` publishes `minLength` and `maxLength` on the models whose
provider documents a cap, and every video model publishes `"pattern": "\\S"`
to reject a whitespace-only prompt at validation. Validating client-side
avoids a rejection late in generation.

## Poll for completion

```bash
curl https://api.hedra.com/web-app/public/generations/{generation_id}/status \
  -H "X-API-Key: $HEDRA_API_KEY"
```

When `status` is `"complete"`, the response includes an `asset_id` for the generated video.
